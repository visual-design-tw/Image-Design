## 使用者會看到什麼

- **繳交有明確完成標準**：填寫或選擇附件、送出、看到「繳交成功」才算完成。只有雲端回傳確切紀錄後才清除草稿及關閉視窗。
- **失敗後不用重新填寫**：文字會暫存在同一瀏覽器分頁；已完成上傳的附件資訊也會保留。失敗時視窗不關閉，可按「重試送出」。尚未完成上傳的本機檔案無法跨重新整理保留，需要重新選檔；登出會清除帳號草稿。
- **不會因重試多交一份**：同一次繳交使用固定請求識別碼。若前次其實已完成，重試只確認原紀錄，不重複新增繳交或通知。確認前次紀錄後，修改過的草稿可依原項目補交規則再次送出。
- **儲存狀態看得懂**：頁面提示「儲存中／已儲存／尚未完成」。一般儲存失敗可重試；如果其他人已更新雲端資料，先保留本機修改，可下載備份，再確認是否放棄本機修改並重新讀取。
- **登入不會無限等待**：一般連線超過 30 秒會結束等待，保留輸入內容並提示再次登入。這是逾時保護，不代表實際 GAS 登入速度已變快。
- **日期與時間操作不中斷**：輸入小時後能繼續點分鐘或按完成，不再重建整個選擇面板；超出有效範圍會顯示具體提示。
- **記住電子郵件，不由網站保存原始密碼**：移除舊版瀏覽器明文密碼資料，密碼交由瀏覽器密碼管理員處理。原有顯示／隱藏密碼按鈕保留。

## 對應原檢查問題

| 原問題 | 本次處理 |
| --- | --- |
| 姓名、組名等文字可能被當成程式 | 補上文字、HTML 屬性、行內動作參數及連結的安全輸出；不允許 `javascript:` 等連結。匯出報表另使用正確 CSV 跳脫，避免 HTML 編碼污染文字。 |
| 記住密碼以明文存入瀏覽器 | 改存電子郵件；啟動及登入時移除舊密碼儲存項目。 |
| 不同小組的繳交編號撞號 | 新增專用 `submitAssignment`，由後端配發唯一編號，另保存 `Request_ID` 去重。相容處理舊版跨組撞號；留言不會因同步而複製別人的既有內容。 |
| 同步失敗卻誤報繳交成功 | 必須收到對應項目、組別、請求的雲端確認；保留視窗、文字與已上傳附件。發布項目失敗同樣保留表單，重試沿用原草稿編號。 |
| 連續修改被舊回應覆蓋 | 儲存回應回來時，保留等待期間新增、刪除及修改的欄位，再依序送出；等待者會等到最新一輪完成。跨裝置版本衝突不自動覆寫。 |
| 刪除後編號重用、復原接錯資料 | 新資料採不重用的隨機唯一識別碼，既有編號不重編；復原前檢查全部集合，撞號整批拒絕，不只跳過主項目。既有衝突不擅自合併。 |
| 兼任身分無法繳交 | 允許具有真實畢製小組身分的形印帳號繳交自己的作業；仍拒絕替其他小組繳交或修改既有紀錄。 |
| 舊請求干擾登出及新登入 | 請求綁定登入階段，忽略過期成功及錯誤回應；登出清除待用大檔視窗連結及草稿。 |
| 網路請求無限等待 | 主頁一般請求 30 秒、上傳請求與獨立上傳頁 120 秒逾時並中止等待。上傳工作階段原有分段重試規則保留；不自動重送整份寫入。 |
| 日期面板失焦時重建 | 改為只更新時間、預覽與錯誤訊息；完成按鈕驗證後關閉面板並還原焦點。 |
| 正式網站與本機版本不同 | 加入介面與雲端版本資訊，缺少或不一致時提示確認更新；正式版本差異仍須透過部署解決。 |

另補上瀏覽器快取儲存失敗的例外保護，不因本機儲存空間不足，把已完成的雲端儲存誤判為失敗。
