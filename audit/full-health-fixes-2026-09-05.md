## 保守相容處理

未附憑證的舊繳交附件保留原檔，不送入自動清理。新的憑證有效 48 小時；過期重新選檔，保留文字草稿。已確認的同一筆繳交重送不再新增紀錄。附件刪除與復原也檢查回收桶中的歸屬及系統根資料夾；新上傳後儲存失敗的清理使用獨立、伺服器內部補償路徑。

舊提醒若只有部分成功總數而無個別收件結果，不能推測哪些人收過信。這些紀錄保留 needsReview／unknown_legacy 供管理者核對，不盲目重寄；新紀錄才有完整逐收件結果。

## 上線條件與限制

1. 必須先啟用並驗證 Apps Script 所屬 Cloud 專案的 Google Sheets API，在測試環境驗收後，再一起更新前端與 GAS。既有授權範圍已包含所需的試算表與外部請求權限。
2. 使用編輯器私有函式 migrateHealthRelease_ 補齊欄位、保留簽章密鑰並遷移既有觸發器；原本沒有提醒排程的不會自行開啟。完整步驟見 [後端部署說明](</Users/james/Documents/Image Design/gas/README.md>)。
3. Sheets batchUpdate 可將同一請求中的更新一起提交；此保證不涵蓋 MailApp 寄信、Drive 或應用程式以外的人工同時改表。[Google 官方 batchUpdate 說明](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate)
4. 寄信完成但執行中斷、或寄送結果未成功存回時，仍存在重寄可能，不能宣稱跨服務 exactly-once。傳輸逾時也不能直接判定「雲端一定沒存到」；程式失效快取並要求重新確認。
5. 尚未測量正式登入速度、真實 Google API 配額、多裝置同時操作、實際收信與 Safari／實體 iPhone。資料寫入改為只處理有變動的資料表，不能僅憑本機測試承諾正式登入必然變快。
6. 本次未更動正式帳號、正式資料、Drive 檔案或排程，也未發送真實 Email。修改前原始碼與測試備份位於 /tmp/shapeprint-before-health-fixes-20260905.tar.gz；它不是正式資料庫備份，上線前仍須另備份試算表與 Script Properties。
